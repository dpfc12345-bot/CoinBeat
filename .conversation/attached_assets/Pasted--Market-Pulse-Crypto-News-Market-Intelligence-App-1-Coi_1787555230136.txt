# Market Pulse — Crypto News & Market Intelligence App

## 1. 프로젝트 목표

코인니스(Coinness)의 뉴스 API를 연동하고, 별도의 실시간 암호화폐 시세 API와 결합하여 **뉴스 + 시장 움직임을 한눈에 보여주는 모바일 중심 금융정보 앱**을 개발한다.

단순한 뉴스 복제 앱이 아니라,

**뉴스 발생 → 관련 코인 식별 → 가격 변화 → 거래량 변화 → 시장 반응**

을 하나의 화면에서 보여주는 것이 핵심이다.

서비스의 임시 이름은 **Market Pulse**로 한다.

---

# 2. 핵심 방향

사용자가 앱을 열었을 때 가장 먼저 알아야 하는 것은 다음 3가지다.

1. 지금 시장에서 무슨 일이 일어나고 있는가?
2. 어떤 뉴스가 중요한가?
3. 그 뉴스 이후 실제 가격이 어떻게 움직였는가?

따라서 뉴스 목록을 단순히 나열하지 말고 **실시간 시장 상황 중심의 UI**로 설계한다.

# 4. 중요한 개발 원칙

## API Key 보안

절대로 Coinness API Key나 기타 API Key를 frontend 코드에 노출하지 않는다.

모든 외부 API 호출은 backend를 통해 처리한다.

Frontend:

GET /api/news

Backend:

Coinness API → Backend → Frontend

환경변수:

COINNESS_API_KEY
COINNESS_API_URL
MARKET_API_KEY
MARKET_API_URL

API Key가 없는 상태에서도 개발할 수 있도록 mock data fallback을 구현한다.

# 5. 메인 화면

모바일 화면을 가장 우선적으로 디자인한다.

전체적인 디자인은:

* Dark mode 기본
* 금융/트레이딩 앱 느낌
* 검정 또는 매우 어두운 배경
* 강한 타이포그래피
* 숫자를 크게 표시
* 불필요한 장식 최소화
* 정보 밀도가 높지만 복잡하지 않게
* 실시간성이 느껴지는 UI

Apple/TradingView/Bloomberg 스타일의 정보 전달력을 참고하되 디자인을 그대로 복제하지 않는다.

# 16. API Architecture

Frontend가 Coinness API를 직접 호출하지 않는다.

다음 구조로 만든다.

Frontend
↓
Backend API
↓
Coinness API

그리고 시장 데이터:

Frontend
↓
Backend
↓
Market Data Provider

Backend에는 Provider abstraction을 만든다.

예:

NewsProvider
MarketDataProvider

초기:

CoinnessNewsProvider
CryptoMarketProvider

향후 다른 데이터 공급자를 쉽게 추가할 수 있도록 한다.

# 27. 중요

지금 단계에서 실제 API가 어떤 response format을 사용하는지 확인되지 않았다.

따라서 Coinness API response schema를 추측해서 하드코딩하지 않는다.

먼저 API documentation 또는 실제 API response를 확인하고,

그 response를 내부 표준 데이터 모델로 변환한다.

예:

interface NewsItem {
id: string;
title: string;
content?: string;
source: string;
publishedAt: string;
categories: string[];
relatedSymbols: string[];
importance?: number;
}

Frontend는 Coinness의 원본 response에 직접 의존하지 않는다.

# 28. 최종 목표

최종적으로 사용자가 앱을 열면 5초 안에 다음을 알 수 있어야 한다.

**① 지금 시장이 오르고 있는가?**

**② 지금 가장 중요한 뉴스는 무엇인가?**

**③ 어떤 코인이 움직이고 있는가?**

**④ 뉴스가 실제 가격에 영향을 주고 있는가?**

이 네 가지를 중심으로 UX를 설계한다.

먼저 Phase 1을 구현하고 실행한 뒤, 브라우저에서 실제 UI를 확인할 수 있도록 해라.

코드를 작성하기 전에 전체 파일 구조와 구현 계획을 짧게 보여주고, 그 다음 Phase 1부터 구현한다.
